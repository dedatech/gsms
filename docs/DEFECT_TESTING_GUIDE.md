# 缺陷跟踪功能测试指南

## 前置准备

### 1. 数据库迁移

启动后端服务，Flyway 会自动执行迁移脚本：

```bash
cd backend
mvn spring-boot:run
```

检查日志确认迁移成功：
```
Successfully applied SQL migration
```

验证字段已添加：
```sql
DESCRIBE gsms_task;
```

应包含以下新字段：
- `severity`
- `reproduction_steps`
- `attachments`
- `fix_version`

### 2. 启动服务

**后端** (端口 8080):
```bash
cd backend
mvn spring-boot:run
```

**前端** (端口 3000):
```bash
cd frontend
npm run dev
```

### 3. 准备测试数据

1. 登录系统: `http://localhost:3000`
2. 创建或选择一个测试项目
3. 添加项目成员（用于分配缺陷）

## 功能测试

### 测试场景 1: 创建缺陷

**步骤**:

1. 进入项目详情页
2. 点击"缺陷"模块标签
3. 点击"新建缺陷"按钮
4. 填写表单：
   ```
   标题: 用户登录失败时无错误提示
   描述: 在登录页面输入错误的用户名或密码后，页面无任何提示
   复现步骤:
   1. 打开登录页面 (http://localhost:3000/login)
   2. 输入错误的用户名 "test123"
   3. 输入错误的密码 "wrongpass"
   4. 点击登录按钮
   5. 观察页面反应

   严重程度: 主要
   优先级: 高
   负责人: [选择一个成员]
   ```
5. 点击"确定"

**预期结果**:
- ✅ 表单验证通过（标题和描述必填）
- ✅ 成功创建缺陷
- ✅ 列表中显示新创建的缺陷
- ✅ 缺陷编号显示为蓝色（如 #123）
- ✅ 严重程度标签显示为橙色"主要"

### 测试场景 4: 状态流转

**步骤**:

1. 创建一个新缺陷（状态：待修复）
2. 点击"查看"打开详情
3. 测试状态流转：

   **流转 1**: 待修复 → 修复中
   - 点击"开始修复"按钮
   - 验证状态变为"修复中"

   **流转 2**: 修复中 → 待验证
   - 点击"提交验证"按钮
   - 验证状态变为"待验证"

   **流转 3**: 待验证 → 已关闭
   - 点击"验证通过"按钮
   - 验证状态变为"已关闭"

   **流转 4**: 已关闭 → 重新打开
   - 点击"重新打开"按钮
   - 验证状态变为"重新打开"

   **流转 5**: 重新打开 → 待修复
   - 点击"设为待修复"按钮
   - 验证状态变为"待修复"

**预期结果**:
- ✅ 每个状态只显示可流转的按钮
- ✅ 状态转换成功
- ✅ 成功提示消息显示
- ✅ 列表刷新显示新状态
- ✅ 不可执行的流转按钮不显示

## 常见问题排查

### 问题 1: 数据库迁移失败

**症状**: 启动后端时报错

**解决方案**:
```bash
# 检查 Flyway 状态
cd backend
mvn flyway:info

# 手动执行迁移
mvn flyway:migrate

# 修复失败的迁移
mvn flyway:repair
```

### 问题 2: 前端无法加载缺陷视图

**症状**: 切换到"缺陷"标签时显示空白或错误

**解决方案**:
1. 检查浏览器控制台错误
2. 确认 `DefectsView.vue` 文件存在
3. 检查 API 接口是否正常
4. 清除浏览器缓存

### 问题 3: 枚举值不匹配

**症状**: 前端显示的枚举文本错误

**解决方案**:
1. 检查前端枚举映射（如 `getSeverityText`）
2. 检查后端枚举定义
3. 确认序列化配置正确

### 问题 4: 状态流转按钮不显示

**症状**: 缺陷详情中没有操作按钮

**解决方案**:
1. 检查 `canChangeStatus` 方法逻辑
2. 确认当前状态正确
3. 检查状态流转规则定义
