## 一、设计背景

### 1.1 现状分析

**已完善的模块（保留不变）：**
- ✅ **需求模块**：表格视图、筛选排序、状态管理
- ✅ **规划模块**：迭代管理、拖拽分配、进度显示

**待完善的模块（重新设计）：**
- ❌ **概览**：当前是占位符，需要展示项目整体健康状况
- ❌ **任务**：当前是"迭代"模块，命名不准确且功能简单
- ❌ **缺陷**：当前是占位符，需要缺陷跟踪功能
- ❌ **报表**：当前是占位符，需要数据洞察
- ❌ **成员**：当前是占位符，需要团队协作功能

### 1.2 设计目标

- **保留现有功能**：不推翻已实现的需求和规划模块
- **完善信息架构**：每个模块都有明确的价值和用途
- **提升交互体验**：减少操作步骤，提高效率
- **统一视觉语言**：遵循ONES设计系统

## 二、8模块总览

### 2.1 模块清单

```
项目详情页 - 8个Tab
├─ 1. 概览 - 一目了然的项目健康状况
├─ 2. 需求 - 【保留】需求池管理
├─ 3. 规划 - 【保留】迭代规划和分配
├─ 4. 任务 - 项目内任务统一管理（三栏布局）
├─ 5. 缺陷 - 缺陷跟踪和修复
├─ 6. 报表 - 项目数据洞察
├─ 7. 文档 - 【暂不开发】
└─ 8. 成员 - 团队协作和贡献分析
```

### 2.2 模块定位

| 模块 | 核心价值 | 主要用户 | 使用频率 |
|------|----------|----------|----------|
| **概览** | 快速了解项目状态 | 所有人 | 高（每次进入） |
| **需求** | 需求池管理和优先级 | 产品经理 | 中 |
| **规划** | 迭代规划和资源分配 | 项目经理 | 中 |
| **任务** | 日常任务执行和跟踪 | 开发/测试 | 高（日常使用） |
| **缺陷** | 缺陷管理和质量保证 | 测试/开发 | 高 |
| **报表** | 数据分析和决策 | 项目经理/管理层 | 低（周期性） |
| **成员** | 团队协作和沟通 | 所有人 | 中 |
| **文档** | 知识沉淀（待开发） | 所有人 | 低 |

### 2.3 导航路径

```
项目列表 → 点击项目卡片 → 进入项目详情（默认显示概览）
         ↓
    用户根据目标选择模块：
    - 看整体进度 → 概览
    - 管理需求 → 需求
    - 规划迭代 → 规划
    - 执行任务 → 任务
    - 跟踪缺陷 → 缺陷
    - 分析数据 → 报表
    - 团队协作 → 成员
```

## 三、模块详细设计

### 3.1 概览（Overview）- 项目仪表板

**设计目标：** 用户进入项目详情页，**5秒内**了解项目健康状况

#### 核心要素

**1. 顶部进度条（首屏可见）**

```
┌─────────────────────────────────────────────────────────┐
│ TeamMaster重构项目                        [详情] [设置]  │
│ 进度: ████████░░ 65%  |  状态: 进行中  |  剩余: 12天   │
└─────────────────────────────────────────────────────────┘
```

**视觉设计：**
- 进度条：蓝绿色（#52c41a），进度条下方显示百分比
- 状态标签：进行中（蓝色）、已延期（红色）、已完成（绿色）
- 剩余时间：12天（黑色）、< 3天（橙色预警）

**2. 关键指标卡片（4列，一目了然）**

```
┌──────────┬──────────┬──────────┬──────────┐
│ 总任务   │ 已完成   │ 进行中   │ 逾期     │
│ 120      │ 78       │ 35       │ 3 ⚠️     │
│ ↗ 12%    │ ↗ 5%     │ →        │ ↘ 1      │
└──────────┴──────────┴──────────┴──────────┘
```

**交互：**
- 点击卡片 → 跳转到任务模块（带对应筛选）
- 箭头表示趋势：↗ 增加、↘ 减少、→ 持平

**3. 迭代进度时间轴（横向滚动）**

```
迭代1 [██████████] 100% ✅  完成于 1月15日  [查看详情]
迭代2 [████████░░]  85% ⚡  预计完成 2月20日  [查看详情]
迭代3 [██░░░░░░░░]  20% 🔄  进行中            [查看详情]
迭代4 [░░░░░░░░░░]   0% 📅  计划4月1日        [查看详情]
```

**交互：**
- 点击迭代条 → 跳转到规划模块（展开该迭代）
- 悬停显示详细信息（任务数、工时、负责人）

**4. 快速操作区（右上角固定）**

```
[+ 新建任务] [+ 新建需求] [+ 新建迭代] [⚙️ 设置]
```

**交互：**
- 点击按钮 → 弹出快速创建对话框（预填项目ID）
- 支持快捷键：N（新建）、I（新建迭代）

**5. 最近活动流（时间线样式，可折叠）**

```
今天
  10:30  张三完成了任务 #123 前端登录页开发
        [任务详情] [重新打开]

  09:15  李四创建了需求 #45 用户权限优化
        [需求详情]

昨天
  16:40  王五开始迭代 #3 开发
        [迭代详情]

  14:20  赵六提交了缺陷 #201 登录按钮颜色不对
        [缺陷详情] [指派给我]
```

**交互：**
- 点击活动 → 跳转到对应详情
- 悬停显示更多信息
- 支持筛选（只看任务、只看需求）

#### 信息架构

```
概览模块
├── 进度区（固定顶部）
│   ├── 项目名称和状态
│   ├── 进度条
│   └── 剩余时间
├── 指标区（4列卡片）
├── 迭代区（横向时间轴）

### 3.4 任务（Tasks）- 三栏布局设计

**设计目标：** 项目内任务的统一管理（需求、任务、缺陷一站式）

#### 核心布局：三栏式

```
+----------------------------------------------------------+
|  🔍 搜索  [类型:任务▼] [状态▼] [迭代▼]      [+ 新建任务] |
+-------------+----------------------------------------+-----+
│             │                                        │     │
│ 迭代树      │   工作项列表                            │ 详情 │
│             │                                        │     │
│ 📁 全部(120)│ ⚪ #123 前端登录页开发                   │     │
│   ├─ 进行中  │   状态: 进行中 | 迭代2 | 张三           │     │
│   ├─ 待办    │   描述: 实现登录页面的UI改造...          │     │
│   └─ 已完成  │                                        │     │
│             │ ⚪ #124 数据库优化                       │ ← 查 │
│ 📁 迭代1(45) │   状态: 待办 | 迭代1 | 李四              │     │
│   ├─ 需求    │                                        │  看 │
│   └─ 任务    │ 🔵 #45 用户登录功能优化（需求）          │     │
│             │   状态: 进行中 | 迭代2                   │  面 │
│ 📁 迭代2(35) │   子任务: 3个 | 进度: 60%               │     │
│   └─ ...    │                                        │     │
│             │ 🔴 #201 登录按钮颜色不对（缺陷）          │  板 │
│ [拖拽区]    │   状态: 待修复 | 优先级: 高              │     │
│             │                                        │     │
+-------------+----------------------------------------+-----+
```

#### 左栏：迭代树

**功能：**
- 展示所有迭代（包括未分配的"全部"）
- 显示每个迭代的任务数量
- 展开子节点（按类型分组：需求、任务、缺陷）
- 拖拽工作项到迭代

**交互：**
- 点击迭代 → 筛选右侧列表
- 悬停显示任务分布（进行中/已完成/逾期）
- 拖拽工作项到迭代 → 更新关联关系

**视觉设计：**
- 文件夹图标（📁）
- 数字徽章（显示任务数）
- 展开箭头（▶ / ▼）
- 拖拽区高亮（拖拽时）

#### 中栏：工作项列表

**视图切换：**
- **列表视图**（默认）：表格形式
- **看板视图**：按状态分列
- **树形视图**：显示层级关系

**类型筛选：**
```
[全部] [任务] [需求] [缺陷]

```

**列表视图：**
```
┌──────────────────────────────────────────────────────────┐
│ #123 ⚪ 前端登录页开发      进行中  迭代2  张三  [详情] │
│ #124 ⚪ 数据库优化          待办    迭代1  李四  [详情] │

**看板视图：**

**树形视图：**
```

## 四、交互流程

### 4.1 典型用户场景

#### 场景1：项目经理查看项目进度

```
1. 进入项目详情 → 默认显示概览
2. 查看进度条和关键指标 → 了解项目状态
3. 查看迭代进度 → 哪些迭代延期
4. 点击迭代 → 跳转到规划模块 → 调整计划
5. 查看报表 → 深入分析数据
```

#### 场景2：开发人员执行任务

```
